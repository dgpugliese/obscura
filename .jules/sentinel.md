## 2023-10-24 - Fix DOM-based XSS in QR Code Generation
**Vulnerability:** The application was using `qrcode.createSvgTag` and injecting the resulting SVG string directly into the DOM using `dangerouslySetInnerHTML`. This is a classic DOM-based Cross-Site Scripting (XSS) vulnerability. If the input string used to generate the QR code (in this case, the `link`) can be manipulated by an attacker, they could potentially inject malicious JavaScript payloads embedded within the SVG structure, which would execute when the browser parses the `dangerouslySetInnerHTML` call.
**Learning:** Even when using seemingly benign data (like a locally generated link), the pattern of rendering SVG strings via `dangerouslySetInnerHTML` is inherently risky and often flagged by security tools. It's an unnecessary exposure when safer alternatives exist.
**Prevention:** Avoid `dangerouslySetInnerHTML` whenever possible. When generating images or visual elements dynamically (like QR codes), prefer generating Data URLs (e.g., `qrcode.createDataURL()`) and rendering them safely using the standard `src` attribute of an `<img>` tag. This completely neutralizes the risk of DOM-based XSS from the generated element.
